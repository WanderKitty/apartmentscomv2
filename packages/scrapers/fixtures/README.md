- **Source:** Aperture — 12727 E Colonial Dr, Orlando, FL 32826 (`https://apertureorlando.com`)
- **Endpoint:** `https://apertureorlando.com/floor-plans/`
- **robots.txt re-check:** `GET https://apertureorlando.com/robots.txt` → HTTP 200, Yoast-generated block, `User-agent: *` / `Disallow:` (empty — everything permitted) plus a `Sitemap:` line; still permits the floor-plans path. - **Capture timestamp:** 2026-08-28T04:16:00Z (server `date` response header from the capture request)
- **Method:** Single `curl` GET request with a normal browser User-Agent, no query parameters, no retries. Response saved byte-for-byte as returned (`content-type: text/html; charset=UTF-8`, HTTP 200). This is this task's one sanctioned capture (two requests total: robots.txt then the page).
- **Saved verbatim to:** `packages/scrapers/fixtures/entrata-embedded-v2.html`

The page embeds its availability data as an entity-encoded JSON array in a Vue component attribute: `<floor-plan-page-main-component ... :floor_plans='[...]' ...>` (single-quoted attribute value, `&quot;`/`&#039;`/`&amp;`/`&lt;`/`&gt;`/`\/`-escaped JSON — not the `jd-fp-data-script-app` script tag used by `entrata-embedded.html`). The array holds 11 per-*floorplan* records (not per physical unit — `available_units` is a count, and per-unit pricing variance lives in each record's own `lease_options[]`), each carrying `post_id`, `title`, `bedrooms`/`bathrooms` (strings), `price_min`/`price_max` (plain dollar-string, no thousands separator), `size_min`/`size_max`, `link`/`link_floorplan`, `is_sold_out`, `available_units`, `pms_id`, `first_available_date` (an empty array `[]` when sold out, or a bare `"YYYY-MM-DD"` string when available — polymorphic on this fixture), `lease_options[]` (per-space-option rent variants, comma-formatted dollar strings like `"1,379.00"`), and a per-record `af3_entrata_options` object (`base_url`, `property_id`, `property_name`, `api_url`, `enabled`) that names the pattern. No photos or other binary assets were extracted from this capture for use elsewhere; the saved HTML is used only as a test fixture (spec §8: no network in tests).

**Knightsbridge not covered by this fixture:** a pre-existing local capture of Knightsbridge's floor-plans page (`https://www.liveatknightsbridge.com/floor-plans/`, canonical URL confirmed in the file), left over in the working scratchpad from an earlier scouting session (not fetched as part of this task's capture budget — read only, no new network request), shows a *different* embedded shape: `<div id="rentpress-app" data-floorplans='[...]'>` with field names `floorplan_code`/`floorplan_post_id`/`floorplan_parent_property_code`/etc, not `post_id`/`:floor_plans`/`af3_entrata_options`. Both sites run the same "Agency Fifty Three" (`af3-*`) WordPress plugin family, but Knightsbridge uses a different shortcode/component than Aperture. Rather than guess a mapping for a shape this task captured no fixture for, Knightsbridge stays `enabled: false`; see the task report. **Covered as of Task 6A** — see `entrata-rentpress.html` below.

## entrata-rentpress.html

- **Source:** Knightsbridge at Stoneybrook — 2802 Cheval St, Orlando, FL 32828 (`https://www.liveatknightsbridge.com`)
- **Endpoint:** `https://www.liveatknightsbridge.com/floor-plans/` (canonical URL and `<title>` confirmed inside the file — genuine, not stale/wrong content)
- **Provenance:** This is the SAME pre-existing local capture described above (`knightsbridge-floorplans.html`, 300,539 bytes), which was already sitting in the shared scratchpad — left over from an earlier scouting session, well before Task 6A. Per Task 6A's compliance instructions, the scratchpad was searched FIRST for a pre-existing capture before any new network request; it was found there (still 300,539 bytes, byte-identical), copied verbatim into this repo path, and used as the fixture. **Zero new network requests were made against Knightsbridge for this task** — no capture timestamp of this task's own is recorded because none was taken; the file's own content establishes the page it came from.
- **Saved verbatim to:** `packages/scrapers/fixtures/entrata-rentpress.html`

The page embeds its availability data as an entity-encoded JSON array in a plain HTML div attribute: `<div id='rentpress-app' data-floorplans='[...]'>` (single-quoted attribute value, `&quot;`/`\/`-escaped JSON — same entity/escape style as `entrata-embedded-v2.html`'s Vue attribute, different host element and field names). The array holds 16 per-*floorplan* records, each carrying `floorplan_code`, `floorplan_post_id`, `floorplan_post_title` (the specific variant name, e.g. "A1 Renovated"), `floorplan_name` (the shared family name, e.g. "A1"), `floorplan_post_link`, `floorplan_bedrooms`/`floorplan_bathrooms`, floorplan-level rent/sqft aggregates, and — the structurally distinct part from every other shape here — its OWN nested `units[]` array with genuine per-*physical*-unit records (`unit_code`, `unit_name` — an apartment number — `unit_available_on`, `unit_bedrooms`/`unit_bathrooms`, `unit_sqft`, `unit_rent_base`/`unit_rent_effective`/`unit_rent_best`, `unit_rent_terms` (a JSON-string-encoded array of per-lease-length rent variants), etc.). Across the 16 floorplans, 37 individual units are nested (some floorplans — sold out / not currently modeled — carry an empty `units: []` and contribute none). `unit_available_on` arrives as `"M/D/YYYY"` (e.g. `"8/6/2026"`), NOT ISO-8601 like every other shape's availability field — the extractor normalizes this (see `packages/scrapers/src/entrata.ts`'s rentpress section) since both the schema (`z.string().date()`) and `extractSnapshot`'s `is_available_now` string comparison require ISO. "RentPress" and the v2 shape's Vue component both trace to the same "Agency Fifty Three" (`af3-*`) plugin lineage but are different shortcodes/components within it — RentPress specifically is documented (Task 6A brief) as a WordPress plugin family that syndicates upstream Entrata/Yardi/RealPage feeds into this common markup, so this extractor is a footprint for discovering other RentPress-powered sites, not just a Knightsbridge-specific fix. No photos or other binary assets were extracted from this capture for use elsewhere; the saved HTML is used only as a test fixture (spec §8: no network in tests).
